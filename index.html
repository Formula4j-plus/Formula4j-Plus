让每一次计算，都有据可依。

为动态表单与业务结果提供后端复算。让前后端共用公式，让计算过程清晰可追溯。

典型使用场景

它更适合做后端统一执行层，而不是仅在页面展示一个公式结果。

报价与计费计算

把前端配置的价格公式放到后端复算，减少订单、报价、折扣规则的结果偏差。

表单与规则校验

对动态表单、审批条件、分值规则做统一复算，作为后端验证与提交兜底。

指标聚合与结果复核

在导入、对账、统计前后执行统一公式，减少人工复核与跨系统口径漂移。

快速开始

先用最短路径跑通一次计算，再根据目标进入使用指南、项目概览或贡献文档。

1. 添加依赖

<dependencies>
  <dependency>
    <groupId>com.formula</groupId>
    <artifactId>formula4j-plus</artifactId>
    <version>3.0.0</version>
  </dependency>
</dependencies>

2. 基本使用

import com.alibaba.fastjson.JSONObject;
import com.formula.calculator.FormulaCalculator;

JSONObject data = new JSONObject();
data.put("price", 100);
data.put("quantity", 5);

String formula = "${price} * ${quantity}";
Object result = FormulaCalculator.calculate(formula, data);

System.out.println("结果: " + result);
// 输出: 500

3. 使用函数

String sumFormula = "SUM(10, 20, 30)";
Object sumResult = FormulaCalculator.calculate(sumFormula, data);
// 结果: 60.0

String ifFormula = "IF(10 > 5, 100, 0)";
Object ifResult = FormulaCalculator.calculate(ifFormula, data);
// 结果: 100

常见问题

先回答适用边界，再决定是直接接入还是继续查看详细文档。

它适合替代前端公式执行吗？

更适合作为后端校验、复算和规则统一层，而不是单纯面向页面展示的前端计算工具。

适合哪些输入数据形式？

兼容入口支持 JSONObject、FormulaData；严格入口直接支持 Map，并保留展示字段映射。

第一次接入应该先看哪份文档？
