# 严格模式与兼容性

当前源码新增显式启用的 `StrictFormulaEngine`。它适用于需要精确十进制运算、类型检查、
嵌套公式、惰性 IF 和错误位置的接入场景。静态 `FormulaCalculator` 继续保留历史兼容语义。
本轮能力仍属未发布变更，已发布的 3.0.0 不应被描述为已经包含新入口。

```java
import com.formula.calculator.core.strict.StrictFormulaEngine;
import com.formula.calculator.core.strict.CompiledFormula;
import java.math.BigDecimal;
import java.util.Collections;

StrictFormulaEngine engine = new StrictFormulaEngine();
CompiledFormula formula = engine.compile("ROUND(${price}*2,2)");
Object value = formula.evaluate(Collections.singletonMap("price", new BigDecimal("12.35")));
// BigDecimal 24.70；编译对象可复用，默认缓存上限为 256。
```

严格入口支持 Map 和既有 FormulaContext，数值返回 BigDecimal，逻辑返回 Boolean。
数字文本需要显式 VALUE；缺失字段报 MISSING_FIELD，null 保持空值，算术不会自动转成零。
错误提供 code、symbol 及从零开始、左闭右开的 UTF-16 原公式区间。

严格模式当前不支持日期、财务、数组范围、脚本和自定义函数。它不是全部 Formula.js 或 Excel 的替代实现。
Formula.js 自身与 Excel 也存在差异；迁移前应查看矩阵并以实际业务语料验证。
