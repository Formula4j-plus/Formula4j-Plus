# Java 17 JMH 基准记录

测量日期：2026-10-13。本轮未发布源码的单机开发基线，用于之后按同环境比较；不代表全部公式或生产服务吞吐。

## 环境与方法

- Windows，Intel Core i5-10400 @ 2.90GHz。
- Oracle JDK 17.0.11+7-LTS-207，JMH 1.37。
- JVM 固定 `-Xms256m -Xmx256m`，1 个线程，2 次独立 fork。
- 每次 fork 预热 3 轮，每轮 1 秒；测量 5 轮，每轮 1 秒；开启 GC profiler。
- 每个线程在计时前检查所有路径的计算结果。各调用包含执行时的数据快照；直接编译路径把编译移出计时。

```sh
java -jar tools/benchmark/target/benchmarks.jar -foe true -jvmArgs "-Xms256m -Xmx256m" -prof gc -rf json -rff baseline-java17.json
```

## 解释与后续比较

这些输入下，严格路径相比兼容路径减少了函数扫描、表达式改写以及中间对象分配。兼容路径为保留历史行为仍逐次构造并扫描处理器，不能据此假设它在其他业务输入下具有同样差距。

严格缓存命中与直接编译复用之间存在误差和运行波动，函数组合的“每次解析”结果也没有形成稳定的耗时排序。不要用这一组均值宣称缓存或某入口在所有情况下固定快多少倍。

函数组合包含 SQRT，十进制求值及其对象分配明显高于简单字段算术。下一步可在语义稳定后评估纯函数常量折叠、数值实现分配和更多真实业务语料。

本次只有单线程、三条公式和一台开发机器。正式业务评估还需覆盖公式复杂度、数据规模、并发、不同 JDK、服务端配置和重复运行；保留原始统计再判断变化。
